# Queue

The ordered queue of changes, one line each with its reason. `/status` prints it; the planner keeps it, citing the data behind each decision against `docs/goals.md`. Every numbered item carries its tier (`T0` to `T6`) and its size (`estimated small`, `estimated medium`, or `estimated large`), and states the problem, its numbers, and the acceptance check rather than the implementation.

1. `workflow-records` (T1 with T4 folded, estimated small): three defects of the delivery workflow's records and waits. (a) A delivery's quality advisories are counted but their text is kept nowhere: `workflow-trim` reported `advisory=4` at aa3bf07 and none reached a run state note or `docs/backlog.md`, so goal 13's "never forgets" fails on every run with advisories; accepted when each advisory of a delivery review reaches the run state or the backlog and the planner can read it. (b) The merger returns pending before CI ends: 2 of 3 merger starts in `workflow-trim` returned pending while CI took 2.45 minutes end to end, and merge took 50 of 161 tool calls (31%) and 11,226 of 112,010 output tokens; accepted when one merger start covers a CI run of up to 30 minutes. (c) An agent is started only to run queued `tools/run_state.sh` lines: record took 1,197 output tokens and 4 tool calls over 2 starts in `workflow-trim` and 761/3 in `agent-authority`; accepted when no agent start exists for that alone and the recorded lines are the same. One domain, `.claude/workflows/deliver-change.js` and its agents. Retrospective notes 1 and 3 of `workflow-trim` and the quality review count at aa3bf07.
