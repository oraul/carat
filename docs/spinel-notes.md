# Spinel notes

Every Spinel pitfall this project has met, once, at the pinned compiler (`SPINEL_REF` in the `Makefile`). Each note gives the rule, why, and what enforces it; a note marked open has an item in `docs/backlog/` and is rechecked when the pin is bumped. The notes are binding for all code under `carat/`, `bin/`, `test/`, and `bench/`: `CLAUDE.md` and `docs/architecture.md` state the rules and point here for the detail. Golden files that follow every note are listed in `docs/examples.md`.

## Language and library

- Standard library only, and only what Spinel bundles: `io/console`, `IO.select`, `IO.pipe`, `Process.spawn`, `open3`, `set`, `forwardable`, `stringio`, `strscan`, `time`, `pathname`, `optparse`. No gems. No `json` library (Spinel documents no parser and refuses `json/pure`), so JSON is `Carat::Json`; no `minitest`, so tests use `Carat::Testing`.
- `IO.popen` is refused at compile time. A child with live pipes is `Process.spawn` with `IO.pipe` pairs; a one-shot command is `Open3.capture2` or `capture3`. The `lint` test also refuses it.
- No `eval`, `method_missing`, `send` or `public_send` with a computed name, `define_method` under a runtime condition, `instance_variable_get` or `instance_variable_set` with a computed name, or `const_get` with a runtime name.
- No custom `hash` or `eql?` on a class used as a hash key, and no array as a key: keys are strings, symbols, integers, or identity.
- String literals are frozen with no opt-out; a mutable string is `+""`, `String.new`, or `dup`. Line arrays hold only strings, and a cell array holds one type.
- `Symbol#to_s` allocates a new frozen String at each call since Spinel 59044ad58, as CRuby's does (at 001419ff it answered one shared copy); a hot path that needs a symbol's text uses `Symbol#name`, which answers the interned copy and allocates nothing, as `Mode.name_of` does for the keymap's lookup on every key.
- `String#inspect` and `#dump` write each byte outside a valid UTF-8 sequence as `\xNN` since Spinel f49716bd, as CRuby's do (at c0502112 they copied the byte), so a message that quotes text with `inspect` shows an illegal byte escaped, as `ManifestCheck`'s problem for an option line that does not read does (`test/domain_plugin_manifest.rb`).
- A `Process.wait` of a child inside a `Fiber`, before any thread starts, ended the program with a segmentation fault up to c0502112; since Spinel c6de72a2 it waits in place and answers the status (a reduced probe crashed at c0502112 and printed the exit status at 0d1a7ca3).
- `private_constant` compiled without being enforced up to 0d1a7ca3 (another class could still read `Owner::NAME`); since Spinel ae6a3602 a read of a private constant through its owner's scope raises `NameError`, as CRuby's does (a reduced probe read `Owner::NAME` from another class at 0d1a7ca3 and raised `NameError` at 2f6c2486), and `Owner.own` reading `NAME` inside its class still answers it. `lint` keeps its rule, which carat's layering asks for whatever the compiler does: every constant of a use case file is in a `private_constant`, and no other file names it.
- Every instance variable is assigned in `initialize`: a call through an unassigned one crashes a release build.
- A method does not both take a block and call itself.
- An exception raised under about 64 nested `loop do` blocks ends the program with `SystemStackError`, so a recursive parser loops with `while true`, as `Carat::Json` does.
- `require_relative` is inlined at compile time, so a missing file is a compile error and the require graph is the module graph.
- `STDIN.raw { }` is the only raw-mode form, and its block holds a single call: Spinel rewrites a short raw block and skips a long one.
- A signal handler sets a flag only, since it runs where Ruby code may run, not inside a blocking call; the loop polls with a timeout. `SIGINT` and `SIGTERM` are trapped before the first thread starts, because once a thread runs an untrapped signal ends the process with no `ensure`, leaving the terminal raw.
- Threads run in parallel with no global lock: shared state goes through a `Mutex` or a `Queue`. A program that starts no thread behaves as single-threaded Spinel, so the editor core starts none; only service drivers do. Ractor is not documented by Spinel and is not used.
- `File.file?` answers true for a FIFO and a character device; `File.stat(path).file?` and `File#stat.file?` on an opened file answer correctly, and `File.ftype` reads the link itself. A `File::Stat` holds its path, not the answer: each reader (`size`, `mtime`, `file?`, `directory?`) calls `stat(2)` on the path again, and `File#stat` on a file opened by path is such a stat of the path, not of the descriptor, so a path swapped after the open is judged as the new entry; only the handle `IO.for_fd` wraps, which has no path, is `fstat(2)`ed. `File.open` of a FIFO for reading while other threads run waits for a writer's first byte or hang-up whatever `O_NONBLOCK` asked, while `IO.sysopen` is a plain `open(2)` with the flags given. `DiskFiles#read_open` therefore opens with `IO.sysopen` and judges the kind on `IO.for_fd`'s handle (Spinel 2f6c2486's `lib/sp_cold.c`, `sp_io_stat_handle` and `sp_fifo_open_read`; `test/drivers_disk_files.rb` fails on a FIFO read through `File.open` beside a thread). `File#read(n)` answers `ASCII-8BIT` bytes, relabeled with `force_encoding(Encoding::UTF_8)`. `DiskFiles` and `test/drivers_disk_files.rb` rely on both.
- Only UTF-8 and binary encodings exist. On text that is not valid UTF-8, `split`, `scan`, and regular expressions raise `ArgumentError`; `length` and `[i, n]` count each byte outside an RFC 3629 sequence as a character, but `index` and `rindex` count a lead byte with the bytes after it as one, and `upcase` and `downcase` read the bytes as other characters. Text from files, names, or registers is cut with `byteindex`, `byterindex`, and `byteslice` (`TextLines.split`), decoded with `Utf8`, and recased over ASCII letters only; `test/domain_utf8.rb` holds the hostile sequences. Since Spinel 84aa303b1 (in the pin since c0502112), `byteindex` and `byterindex` raise `IndexError`, as CRuby's do, for an offset on a continuation byte (0x80 to 0xBF) of any text not binary, valid or not: a search from an offset that may fall inside a character or after a stray byte starts at `Utf8.boundary`, which skips them (`PluginApi::Paths.segments` inlines it).
- `Regexp.new` on a runtime string compiles to the engine Spinel bundles. A pattern with a back reference, a look-around, or an atomic group runs on a backtracking engine whose step limit raises `RegexpError` (a few milliseconds); every other pattern runs without backtracking, in time about the characters scanned times the pattern's size (300 states over a million characters took 1.3 s), and a counted repetition is expanded when compiled (`a{1000}{1000}` took 0.6 s). `Regexp#match(text, pos)` takes and `MatchData#begin` and `#end` give code point indices, a `pos` on text that is not ASCII is found from the start of the line, so each call may cost the line's length whatever it scans, `^` and `\A` do not match at a later `pos`, `String#byteindex` takes no `Regexp` (`NoMethodError` when it runs), and inside a class `&&` is an intersection, so a literal `&` is escaped. A `Regexp` or `MatchData?` signature is not applied (a warning). Search therefore translates Vim patterns into non-backtracking constructs only, caps their size, and charges every match to a budget before it runs (`VimPattern`, `Search`, `docs/compatibility.md` Search).
- Open: `line[i, 1]` on a line that is not ASCII is resolved from the start of the line, so a loop of one-character slices is quadratic on a long UTF-8 line. Walk code points with `Utf8.size_at` and `code_at`, or compare bytes (backlog: "Some per-command character loops still slice one-character strings"). Rechecked at 2f6c2486: still open; a reduced walk of one-character slices took 28 ms over 10,000 `é` and 359 ms over 40,000, against under 1 ms for ASCII lines of those lengths.

## Records

- Immutable values are `Data` subclasses (`class Position < Data.define(:row, :col)`), mutable records are `Struct` subclasses with `keyword_init: true`, both in the subclass form only: inline RBS inside the block form is ignored, and `Struct.new` with a string name, `define_method` in the block, and singleton methods on an instance are refused. `lint` checks `keyword_init: true` on every `Struct.new`.
- Every record is built with keyword arguments at every call site (`Position.new(row: 0, col: 0)`): a positional call of a `keyword_init` record raises `ArgumentError`, and a keyword `Data` construction compiles to the same C. `lint` checks every `Name.new(` of a record and every bare `new(` in a record's file.
- A keyword `super` of a `keyword_init` record must name every member. A record that sets only some calls `super()` and stores every member through its writer, as `Buffer`, `PluginEntry`, and `Registers` do.
- A `Struct` record's methods use the readers and the `self.member =` writers, never instance variables, and every member is pinned with a `# @rbs @member: Type` line at the top of the class.
- An empty array literal is typed `Array[Integer]`, and a pinned member of another element type does not coerce it inside a `super` call: a record whose default is an empty collection of another type calls `super()` and stores the literal through the writer, as `Keymap` does. `Buffer` stores its line array the same way, and `LineSplice` writes the array one element at a time.
- `# @rbs @member` pins apply to a `Data` subclass only when the class body holds at least one statement, so a pinned value has at least one method. A pinned hash member refuses an empty hash literal passed to the constructor, so a member callers may fill with `{}` stays unpinned.

## Signatures and inference

- Every method, attribute, and instance variable under `carat/` carries inline RBS in Spinel's comment form: `#: (String) -> Integer` directly above a `def`, a `# @rbs @name: Type` block at the top of a class, a trailing `#: Type` on each `attr_*`; no sidecar `.rbs` files. Spinel applies them before inference and trusts them unverified, so a signature describes what the program stores, `untyped` where a value is genuinely mixed. `lint` fails on a missing one; `make types` prints what was inferred and where it widened.
- Optional, rest, and keyword-splat parameters get no seed, so methods take required parameters only. Required keywords are typed fully, also through `super(kind: kind)`.
- A keyword default such as `store: Store.new` is typed, but evaluated again on every call, so two objects built with the default do not share it. Defaults are allowed only for a collaborator with no arguments, no state, and no I/O; everything shared is a required keyword built once in `EditorAssembly`, and `test/adapters_assembly.rb` checks every holder got the one instance, through its reader or the assembly's wiring ledger.
- The return type of a method a subclass overrides (every port method and its driver and double overrides) is not applied: give it `# @rbs name: Type` parameter lines, or `# @rbs skip` when it takes none, and describe the return in prose. A `-> void` return is annotated normally.
- `Array[T]` and `Hash[K, V]` pin only with builtin element types, and `Symbol` is not one: an `Array[Symbol]` signature is not applied, so such a parameter is `untyped` and checked with `is_a?`, and a `Hash[String, Symbol]` pin leaves the values `untyped`. A `Hash` pins only with `String` or `Symbol` keys, and a hash literal whose key is a constant reads as `Hash[untyped, untyped]`: write the key as a literal.
- A nullable local keeps its nullable type after a `nil` check, and reading its members widens what they are stored into: pass it through a helper typed as never nil, as `Position.sure` is.
- A concern whose results widen in `make types` becomes a module function, as `Boundary.copied_lines` did; a list of objects of a program class is a class of its own with a pinned `Array[untyped]` and a typed reader, as `PluginEntries` is; `make lint` refuses an `Array[untyped]` parameter but the element reader `(Array[untyped], Integer) -> T`, and a pinned list assigned from another file.
- Spinel drops a method whose name nothing in the program holds, unless it is the last statement of its class or module body, before types are read, then warns that its signature is not applied ("its declaration became a NilNode"): `carat-gen-config` calls only `Utf8.size_at`, so `Utf8` names `boundary` and `scalar?` with `public_class_method`, a no-op for public methods. A Spinel warning (`spinel: FILE:LINE:COL: warning: ...`, or `spinel: warning: ...` without a location, such as a dropped `--rbs` ivar pin or inference that did not converge) fails `make dev-build`, `test-build`, `build`, `test-one` (so `lint`), `bench`, `bench-budget`, `types`, `gen-config`, `diagnose`, and `diagnose-one` (`tools/spinel_warnings.sh`); `spinel-doctor --quiet` hides it, so those two run Spinel through the script; `build` and `gen-config` then remove the binary `spin` wrote, which it would otherwise call up to date and not compile again.

## Analysis, tests, and the runner

- Spinel types a method's parameters once for the whole program, and every test is in one runner, so an `untyped` argument (a table row's value, anything read from an untyped array) widens the library method it reaches for every test, and the analysis pays with re-narrowing rounds: `test/domain_buffer.rb` once took 5 rounds and 40 seconds instead of 2 and 23. Convert table values with a typed helper (`strings`, `ints`, `.to_s`, `.to_i`) before the call, as `test/domain_edits.rb` does; a test of a refusal of a wrongly typed value is the exception. `make test-build` fails above 2 rounds.
- Spinel 2440954d1 is a compile-time regression, so the pin stayed at its parent 6af548c9 until carat's untyped reads were removed, and a bump past it is checked for compile time, not only for rounds: there each `[]` on an untyped receiver rebuilds the position map, a cost that grows with the untyped calls times the record classes. The runner compiled in 125 s at 6af548c9 against 412 s at 2440954d1, with 39 code generation rebuilds against 4,501, and `make test-build`, `make diagnose`, and CI's compile step took about four times as long at 6b43fe94. A standalone probe of 300 record classes and 400 untyped `[]` calls compiled in 12.0 s against 5.2 s with the calls typed; with no record classes, untyped calls cost little. The construct to avoid is a `[]` on a receiver Spinel types `untyped`, such as a table row or anything read from one: from 2440954d1 on, each one generated costs two rebuilds of the load record (`SP_TIMING` prints them as `phase=an_elab_points ... builds=N`), and a `.to_s` or `.to_i` after the read does not help, since the receiver decides. A typed receiver costs nothing whatever its elements, so read an untyped array through the element reader `(Array[untyped], Integer) -> T`, as `Testing#table` reads its rows through `cell`, and give a table whose every input is an array literal to `Testing#cases`, whose block gets its input typed `Array[untyped]`. With those (untyped-elephant), the runner at 6b43fe94 makes 1,181 rebuilds instead of 4,501 and spends 131 s instead of 413 s in code generation; at 6af548c9 it stays at 39. Read a parsed JSON value through `Carat::Json.field`, `element`, and `reach` (a dotted path, `"params.position.line"`), whose `[]` is on a receiver typed `Hash` or `Array`; with those in the language-server tests (untyped-gateway), the runner at 6b43fe94 makes 779 rebuilds instead of 1,181 and spends 100 s instead of 152 s in code generation, still 39 at 6af548c9. With the gateway's and `SymbolOutline`'s own reads and the test helpers and loops the trace named read the same way, an untyped array or a value read from one through `Carat::Json.element` (spinel-untyped-bump), the runner at Spinel b582d53e makes 125 rebuilds instead of 731 and spends 20 s instead of 104 s in code generation, 2 min 52 s in all instead of 4 min 32 s. What is left: FileUtils (bundled, 26), a few untyped reads in production code (`MainLoop#run` 8, `ManifestCheck` 12, the manifest descriptions 5, `EditorAssembly` 4), `PluginsRubyTest` 8, `EditorTabsTest` 4, and rebuilds asked by calls other than `[]`, 2 or 3 per method. With that, the pin moved to 93d7883b (spinel-untyped-bump-b): the runner makes 125 rebuilds there, `an_elab_points` 10.9 s within code generation 19.3 s, analysis 138.6 s at 4 fixpoint and 2 re-narrowing rounds, and on four cores `make test-build` took 169 s and `make diagnose` 219 s, with allocations and rounds equal to 6af548c9's.
- Open: values destructured from an array inside a method (`a, b = helper`) lose their types; in one test the generated C did not compile. A helper returning several values returns an object with typed readers (backlog: "Spinel loses the types of an array destructured inside a method"). Rechecked at 2f6c2486: still open as far as a probe can tell; a reduced probe the size of the f34005bf one (five values of five classes destructured twenty times in one method, one assigned through an attribute chain) keeps its types and answers correctly, so only reverting a helper decides it.
- A module function sharing its name with a reader that some call reaches through a receiver of several classes can leave that call unresolved (`make diagnose` reports it): `ExRange.number` beside `PluginApi::Response#number` did, until it became `line_number`. A program method named after a builtin `String` method does the same in the bundled packages: `FollowPalette#chars` left the `each_char` calls of fileutils unresolved until it became `char_count`. Give such a method a longer name.
- `NameTest.main if __FILE__ == $0` is folded at compile time: true when the file is the compile root (`make test-one`), false inside the runner.
- `-O 0` and `--incremental` are development modes with the same answers and slower code; the release binary is always `spin build` at `-O 2`. On four cores the runner's C compiles in about 9 seconds at `-O 0`, 30 at `-O 1`, and 46 at `-O 2`. Allocations per key are the same at every level, so the allocation budget builds at `-O 0`.

## Known miscompilations

- Open: some string returns answer the method's argument: a `case` of string-literal branches called with a literal, a ternary of `""` and an indexed `to_s` in a two-parameter method, a guard return of the argument before a `byteslice(...).to_s` result, and a constant array's `include?` of a reader on a `Data` value. Rewrite as guard returns or through a local, and let a table test catch it (backlog: "Spinel answers a method's argument for some string returns"). Rechecked at 2f6c2486: the four reduced shapes still answer correctly, as at f34005bf, so only reverting the rewritten places decides it.
- Open: an empty array literal passed to a method that appends to it comes back empty (an array holding an element keeps the appends): a method that fills an array returns it and the caller assigns the result, as `Config#merge_runs` does (backlog: "Spinel drops appends to an empty array literal passed to a method"). Rechecked at 2f6c2486: a reduced fill of an empty literal keeps the appends, as at f34005bf, so only reverting `Config#report` decides it.
- Open: the runtime releases free slab chunks with `MADV_DONTNEED` on huge pages, so single keys can stall 8 to 12 ms on a host with `madvise` defragmentation; `SPINEL_SLAB_HUGE=0` avoids it (backlog: "Spinel's slab release stalls keys on transparent huge pages"). Rechecked at 2f6c2486: still open; `lib/sp_slab.c` still releases with `MADV_DONTNEED` and marks arenas `MADV_HUGEPAGE` unless `SPINEL_SLAB_HUGE=0`.

- Open, new at f34005bf: a method a later file may still redefine gets a versioned entry (`NAME_entry` in the C) that picks the definition by load-time flags and falls back to the superclass's. Its parameter takes the call's argument class while the dispatch casts to the base signature, so `PluginRegistry#activate_all` passed a `Host` where each plugin's entry took a `PluginLink`: the entry's link is typed `PluginApi::Host?` and stored through `PluginEntry#attach`, since a `PluginLink` written into the `Host` member through the Struct writer was not upcast either. Its return joins a raising base's `nil`, so the readers of `Host#icon`, `Host#stat`, and `FilePort#stat` results went unresolved in `make diagnose`: those bases answer a failed or missing value instead of raising (backlog: "Spinel f34005bf miscompiles versioned entries and case constants"). At 2f6c2486 a reduced probe (a raising base `Host#stat` and a subclass `Link` defining `stat` twice, called from a method taking the base) answers correctly, as it did when written on 2026-11-14, so it does not reproduce the defect met in the plugin registry, and only reverting `PluginEntry#attach` and the non-raising bases decides it.
- Open, new at f34005bf: a `when CONST` whose bare name another scope defines with another type is folded to false, qualified or not (`when VISUAL` in `Mode.visual_kind` read `Highlight::VISUAL`, an Integer); compare with `==` in guard returns instead. A bisect of the reduced probe names Spinel ade8cfe2, "Constants keep the names the program wrote; their slots go by the record's keys". Same backlog entry. Rechecked at 2f6c2486: still open; the reduced probe (`Mode::VISUAL` a Symbol beside `Highlight::VISUAL` an Integer) answers `:none` for `:visual` at c0502112, 0d1a7ca3, and 2f6c2486.

## Toolchain

- `spin` treats every visible directory as project source (it reports foreign `.c` files and feeds every `.rbs` to the compiler), so the Spinel checkout and the toolchain live in the hidden `tmp/.spinel` and `tmp/.toolchain`, and generator templates live inside `tools/new.sh`, not as `.rb` files.
- `spin test` compares a program without a snapshot against `ruby` from the `PATH`, and `--regen` writes snapshots from it. Every `make` target puts the refusing stub `tools/noruby/ruby` first, `make no-cruby` proves it, and tests and snapshots run only through `make`.
- Spinel's build generates one header with a CRuby script; it is vendored as `tools/spinel/spinel_rt_responds_generated.h` and regenerated in the pull request that bumps `SPINEL_REF` with `make spinel-header`, whose `tools/spinel/gen_respond_to_tables.rb` ports the script's reading part to Spinel (it matched CRuby's output byte for byte at 001419ff). A bump whose generator scripts in Spinel's `tools/` changed ports the change there first.
- Open: `make types` leaves `build/carat.rbs`, which later `spin` runs fail to parse and warn about; delete it after use (backlog, `docs/backlog/Makefile.md`: "make types leaves build/carat.rbs that a later spin build warns about").
- `spinel-doctor` (`make diagnose`) must report clean; its behavior leg compares against a CRuby and is always skipped, and its advice lines show where a signature is worth tightening.
