# Codebase map

Where everything is, by area. Read the section of the area a change touches, then only the files, tests, and design sections it names. `docs/architecture.md` is the binding design; this map is the index into the code. Every file under `carat/`, `bin/`, `test/`, `bench/`, and `tools/` has its home in exactly one area, under its Files or its Tests (a test's `.expected` snapshot goes with its test), and `test/lint.rb` fails when a file is missing here or a path named here does not exist. A change that adds, moves, or removes a file updates its area in the same pull request.

Method names are given without line numbers; find them with `grep -n "def name"`. Designs are archived OpenSpec changes under `openspec/changes/archive/`, named without their date prefix, with the sections that explain the area.

Areas:

1. Build and CI
2. Toolchain
3. Configuration
4. Composition and state
5. Grammar and keymap
6. Motions and text objects
7. Operators and registers
8. Edit path, transactions, and insert mode
9. Undo and repeat
10. Visual modes
11. Windows and tabs
12. Ex commands, the command line, and files
13. Rendering
14. Syntax highlighting
15. Plugin host and API
16. Explorer plugin
17. Ports, drivers, and language services
18. Tests and benchmarks

The last section, Delivered changes, lists every change merged so far in order with what it left for later.

## 1. Build and CI

What: builds with `spin`, maps commands to `make` targets, runs the checks locally and in CI, and keeps the pipeline's run state and gates.

Flow: `make build` (release, `build/bin`) and `make dev-build` (development flags, `build/dev/carat`, analysis budget checked). `make check` runs `CHECK_STAGES`; the checker runs `FAST_STAGES` (`make stages`; origin/main's `CHECK_STAGES` while its Makefile has none, `main_stages`) through `tools/run_state.sh check`, `CHECK_JOBS` logged stages at once in the order they need (`STAGE_AFTER`, `STAGE_ALONE`), in a throwaway clone outside the delivery clone, detached from it and ending in a verdict line by which the workflow reruns a killed, superseded, or escaped check (files changed only under the main checkout's `build/` paths `LANE_WRITTEN` names, none by default) with no fix round, and CI mirrors them after `tools/ci_scope.sh`, its differences recorded in the Makefile. `.claude/workflows/deliver-change.js` runs the agents, from the planner to the retrospective, which closes a run in one start (its last records, proposals, and the report), no quality reviewer among them (the contributor's own quality review, `qualityReviewProblem` and `qualityStep`, comes before the archive), and, before the package step, one closing contributor start (`close-advisories`, `closeAdvisories`) for the advisories left in the change's own files, outside the fix rounds; `/sprint` runs `.claude/workflows/sprint-planning.js` once a sprint's six changes merged (five before sprint-17) (the security review of its combined diff, continued once over the files it left (`reviewContinued`, `stillLeft`), its findings noted from the reviewer's result, the whole-tree `.claude/workflows/periodic-review.js` every second sprint, and the planner's sprint mode, which reviews the diff's quality and returns its kept notes, disputes, and the security findings the reviewer missed (`missedSecurity`, `qualityReviewed`), recorded as single-quoted words (`reviewNotes`) through the security reviewer's guarded record mode (`recordNotes`), and whose `build/plan/` files the next delivery's package step applies once with `groom`, held by a blocking sprint security finding or the plan's security first (`queueHeld`, `queueLine`, the run state's `hold`); a delivery's planner writes `build/plan/<change>/`, which its package step applies for its own lane with `plan-apply`); `tools/run_state.sh push` runs `tools/gates.sh`, and the merger, which also waits for CI, runs the copy of a fresh worktree of `origin/main` at `tmp/.merge-gates`, after `git fsck` hashed every object of the shared store and `git diff --quiet`, over an index `git read-tree` reset to main's tree, hashed every tracked file of the copy against it, with no `refs/replace` entry standing (a stop that fails closed when `for-each-ref` fails) and every git of the line run with `--no-replace-objects`, so no object branch code planted, swapped back, or wrote into the copy reaches it. The `metrics` stage writes `build/metrics/current.tsv` with `tools/metrics.sh`, which `tools/run_state.sh bench` compares with main's recorded figures (the newest merged change without a history row, else the last row), the benchmark agent with `main` when they differ, and CI with the last push to `main`; the run state keeps each run's figures until the next change appends them to their lane history, `docs/metrics-feature.tsv` or `docs/metrics-backlog.tsv`.

## 12. Ex commands, the command line, and files

## 13. Rendering

What: paints the state into flat frames from decoded lines and writes only the changed cells to the terminal.

Flow: `EditorAssembly#render` runs `ArrangeView` and `HighlightView`, then `FramePresenter#call(state)` paints every window of the current tab page (sign column, the visual selection, the syntax tokens from `SyntaxCache#lookup`) with a `WinSeparator` row under each window above another, the buffer tabs row through `TabBar#paint` when `BufferList#tab_row?`, the one status bar through `StatusBar#paint`, the floats and the notifications through `FloatPainter#paint`, and the message row from decoded lines (`LineCache#fetch`, `DecodedLine.decode`) into one of two `Frame`s in turn, painting a row only when `PaintedRows` says what it shows changed and recording dirty rows and a full-width window's scroll; `ScreenPresenter#present(frame)` writes the changed runs of the dirty rows, scroll regions, or a full redraw, in one `TerminalPort#write`, each group in its `SgrTable` sequence. While the `StartScreen` shows, the presenter paints its `StartArt` frame over the current window after the windows.

## 15. Plugin host and API

What: the plugin API every plugin requires and the host that registers plugins, routes actions, ex commands, and prompt answers to them, delivers events, and serves their requests.

Flow: `EditorAssembly` registers `Plugins::Registry.all` with `PluginHost#register` (`PluginRegistry#register`, every manifest rule in `ManifestCheck.check`) and calls `prepare_all` once every ex command is registered, which merges each enabled plugin's bindings without activating it: `PluginRegistry#activate` runs a plugin's `activate` on its first trigger (`PluginRouter#action` and `#command`, `PluginSyntax#provider`), or at the first idle after the first frame (`PluginHost#idle`, from `InputController#pump`) for a plugin that declares no action, ex command, or filetype; events reach only an active plugin, and a plugin subscribed to `resize` hears the current size right after its activate. A `plugin.<name>.<action>` binding reaches `PluginActionHandler` through the action table's namespace and `PluginHost#action` → `PluginRouter#action`; an unknown ex command reaches `PluginCommandHandler` (registered last) → `PluginHost#command`. Every call into a plugin goes through `Guarded#guarded`, which disables and cleans up a plugin that raises. A plugin calls its `PluginLink` (a `PluginApi::Host`), which refuses a disabled plugin and forwards to `BufferRequests`, `WindowRequests`, `FileRequests`, or `UiRequests`. After each key `HandleKey` calls `PluginHost#observe`; `PluginEvents` compares the state, queues events caused during plugin calls, and delivers them after the outermost call in bounded rounds.

## 17. Ports, drivers, and language services

What: the interfaces the core uses to reach the terminal, files, clock, configuration, signals, child processes, and language servers, the drivers that implement them, and the language server client.

Flow: each port is a class whose methods raise `NotImplementedError`; drivers subclass them and are built only in `bin/carat.rb`; doubles (area 18) subclass them for tests. `MainLoop#run` polls the `SignalPort` (terminate, resize), renders on a resize, and pumps input. On an idle read `InputController#pump` calls `LanguageServicePort#poll`: `JsonRpcLanguageGateway` drains at most 64 queued `ServiceMessage` values that `ProcessRunner`'s reader threads framed with `RpcFramer`, starts the current buffer's server when the working directory is under a root of `language.trusted_roots` (else the slot reads `untrusted :LspStart`), sends `didOpen`, `didChange` by the announced `textDocumentSync` kind (2 one ranged change from the lines last sent, 1 the whole text, else none), `didSave` (reported by `SaveFile`), and `didClose`, and writes the `lsp` slot through `StatusSlots#set_lsp`; `bin/carat.rb` calls `stop` in its `ensure`. The completion source `ServerCompletions` records the wanted word in the `CompletionRequest` it shares with the gateway, which sends `textDocument/completion` after a 0.1 second debounce, cancels a stale request, and keeps the bounded answer for the popup. `K` (`DocsHandler`, `RequestHover`) records a hover ask in the `HoverRequest` the gateway shares, sent as `textDocument/hover` at the next idle tick; `InputController` hands the arrived answer to `ShowHover`, which opens the documentation float, `HandleKey` closes it through `FollowHover` when the cursor moves, and `PinHover` copies it into a split.
