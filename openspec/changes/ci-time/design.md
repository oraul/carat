# Design

## Context

`tools/ci_scope.sh` answers `run=true|false` for the spin job: it skips the checks when every path of the merge commit's diff against its first parent is documentation no test reads, or when a push to main has the tree of a pull request head whose spin check passed. `documentation()` matched `.claude/*`, though `tools/tools_test.sh` reads the agent files, the workflows, and `.claude/settings.json`. The only CI figure in the run state is `metric.ci_min`, the merger's minutes from the first check's start to the last one's end (`.claude/workflows/deliver-change.js`). The script measures each phase with `budget.spent()`, output tokens only; total tokens reach the run state only through `run_state.sh usage`, one figure per Workflow start (openspec/changes/archive/2026-11-04-pipeline-speed/design.md).

## Decisions

- Since the last green run. On a pull request whose diff against the base is not all documentation, `ci_scope.sh` lists the pull request's commits (`gh api repos/R/pulls/N/commits`), walks back from the newest commit before the head, at most `GREEN_LOOKUPS` (10), and takes the first whose spin check passed. It fetches that commit and diffs it against the checked-out merge commit: when every changed path is documentation no test reads, the checks are skipped. The merge commit holds the base, so a base that moved with code since the green run shows up in the diff and runs the checks; a green run that was itself skipped passed against a commit whose code equals this one's, by the same rule. Any call that fails runs the checks.
- `.claude/agents/*`, `.claude/workflows/*`, and `.claude/settings.json` are code: the brief names them and `make tools-test` reads them. The other `.claude/` paths stay documentation.
- Per-stage timings. `run_state.sh ci-stages CHANGE COMMIT` finds the newest run of the `ci` workflow at the commit and reads its spin job's steps through `gh api`, the seconds computed by gh's `--jq` (`fromdateiso8601`). It drops the earlier `metric.ci.*` keys and writes one per step that took a second or more, its key the step name in lowercase with every other character an underscore, at most 32 characters. It exits 0 when nothing could be read, so the merger's green and red lines, which run it first after the figures, never stop on it. The merger runs the line only once every check finished, so the run is complete.
- Waiting calls. The merger's waits are 180, 240, then 300 seconds, so its `waited` minutes give the number of waits (`waitsOf`, which `mergerCap` now uses too); each wait costs two calls, `ci_wait.sh` and the read after it. The script sums them over the merger's starts into `metric.ci_wait_calls`, beside `phase.merge`'s calls in the metric line.
- Weighted tokens. The runtime writes each Workflow run's agent transcripts under the session's directory: per agent `agent-ID.jsonl`, whose assistant lines carry `message.id`, `message.model`, and `message.usage` (one API response repeated on several lines, so the last line per id counts), and `agent-ID.meta.json` with `description` (the label) and `workflowPhase`. `run_state.sh tokens CHANGE DIR` reads them with awk, prices each start by `TIER_PRICES`, and records `metric.start.N` "KEY/TIER/TOTAL/WEIGHTED", adds to `metric.weighted.KEY` "TOTAL/WEIGHTED/STARTS" and `metric.weighted_tokens`, and appends the directory's name to `metric.counted`, refusing a directory already counted. `/deliver` runs it after each Workflow start with the run's transcript directory.
- The history keeps its 18 columns in place, since `rates`, `review_due`, and `sprint_state` read columns by number, and appends `ci_stages` (`group ci`), `ci_wait_calls`, `weighted_tokens`, and `weighted_phases` (`group weighted`). The existing rows get `-` in the four, so every row has the header's columns.

## Risks

- The transcript format is the runtime's, not a published interface: a field renamed makes `tokens` record zero starts, which it prints, rather than a wrong figure.
- `ci-stages` and the green-run lookup depend on `gh` being authenticated; both fall back (no stages recorded, the checks run).
