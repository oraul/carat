# Proposal

## Why

The session's pull request tool appends a "Generated by Claude Code" footer with the session link and id when it creates a pull request, so every pull request from #95 to #104 keeps that revision in its edit history even after the contributor set the body back to the gated file: a hard-rule exposure the user removes by hand. Decision 17 of the pipeline review (the user's request) replaces the tool with a script that writes the gated text and nothing else. This change is outside the roadmap of `docs/architecture.md` section 12: it is delivery tooling that closes a hard-rule exposure.

## What Changes

- Add `tools/publish_pr.sh CHANGE TITLE`: it runs the pr-body gate on `build/pipeline/CHANGE.body.md` and scans the title with `tools/scan_text.sh`, refusing before any network call when either fails; it then creates the pull request through GitHub's REST API with `curl` (head the run state's branch, base `main`), or updates the title and body of the one the run state already records, reads the live title and body back, and refuses, reporting the difference, unless they equal the gated title and file byte for byte. It records the number in the run state (`pr`) as soon as the pull request exists, so a retry updates instead of creating a second one, and prints it.
- Add the `/publish-pr` command (`.claude/commands/publish-pr.md`), which runs the script.
- Change `.claude/agents/contributor.md`: the package step publishes with the script in place of the pull request tool, the re-read step goes (the script does it), the body mode updates through the script, and the frontmatter drops the create and update tools.
- Change `tools/agent_guard.sh`: the contributor profile may run `sh tools/publish_pr.sh CHANGE TITLE`.
- Add `tools/tools_test.sh` cases with a stub `curl`: a body failing the gate is refused before any call, a live body unlike the file is reported and the script fails, the number is recorded and printed, a recorded number updates instead of creating, and the guard's contributor form.
- Update CLAUDE.md, README.md, `docs/codebase-map.md` area 1, and the Makefile's `tools-test` description; the plan's queue and backlog entries.

Out of scope: the workflow, which names no pull request tool and reads the number from the package result as before; the merger's tools (read and merge); removing the footer revisions of #95 to #104, which the user does; any token handling, since the session's proxy authenticates calls to the API host.

Assumptions:

- The API base is written split (`"https:/""/api.github.com"`), as `tools/tools_test.sh` already writes a hosted address, so the scanner's URL rule holds for the file; no address appears in any doc.
- The title is gated by the same scanner the pull request scan runs on it, plus one non-empty line; the Conventional Commits shape stays the contributor's duty, as before.
- `jq` builds the request and reads the response; it is on the session image and the CI runners, as `curl` is.
- The script records the number itself (`run_state.sh set CHANGE pr N`) besides printing it, so the acceptance "the number recorded" is checked by the script's own test.
