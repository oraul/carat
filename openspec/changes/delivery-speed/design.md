# Design

## Context

`.claude/workflows/deliver-change.js` runs the phases; `tools/run_state.sh` is the one writer of the run state; `tools/gates.sh` holds the pre-push and merge gates, the merge running origin/main's copy; `tools/agent_guard.sh` keeps each agent to its commands. The figures are those of `tmp/briefs/pipeline-skeptic.md` decisions 11 and 14.

## Decisions

1. Late findings. After the package step, `handOver()` is no longer passed to a push: each finding is queued as `note CHANGE late-finding "TEXT"`, its text reduced to a shell-safe set of characters (`noteText`), a line the closing start's profile already runs. `append_history` appends, for each merged run it adds a row for, that run's `late-finding` notes to `docs/backlog.md` as one entry, so the next change's package step commits them with the metrics row. A run pushes once, plus once per CI fix, as the push command already enforces.
2. Checks once. `FAST_STAGES` in the Makefile is what `make stages` prints and the checker runs: docs-lint, dev-build, test-build, test-run, diagnose, bench-budget, metrics, gates. `metrics` and the builds it reads stay because the benchmark phase compares the checker's measurement with main's figures; diagnose and gates stay because CI does not run them on a pull request. CI runs every stage of `CHECK_STAGES` but diagnose and gates, the release build and its smoke test moving onto pull requests, so each stage runs at least once per pull request and the overlap is the tests and the measurement. `make check` keeps the full list for a push by hand. `gate_stages` reads `FAST_STAGES`, else `CHECK_STAGES`. Since the merge gates run origin/main's copy, `check_stages` runs origin/main's `CHECK_STAGES` while its Makefile defines no `FAST_STAGES`, so the change that adds the list still passes main's gates.
3. Quality narrowed. `quality-reviewer.md` blocks only on a correctness bug or a behavior change without its test; every other point is an advisory, recorded as now, until `sprint-planning` adds the broad review.
4. Backup removed. `backup_branch`, `restore_branch`, `drop_backup`, the `backup`, `restore`, and `abandon` commands, the `backup` key, the guard's `contributor:backup` form, the gates' `backup` group, and their cases go; `backup` and `abandon` now exit with the usage. Commits not pushed stay on the local branch, which a resume checks out.
5. Superseded red. `merger.md` reads only the newest run of each check name on the head. The workflow's `staleRed(checks)` returns true when every check name's last listed run passed; a red result whose checks say so is asked again (a wait), never a fix round.
6. Fix-round scope. Each review is told the commit of its last passed review of this start (`narrowedFrom(ran, KIND, head)`, never a pass only the run state holds, which branch code run by the checks could have written) and reviews `git diff COMMIT HEAD`, marking only what that diff introduces as in the change. `reRaised(finding, earlier)` matches a blocking quality finding's file and line against the run's earlier advisories; a match is kept as an advisory and blocks nothing. Security findings are not re-rated: `securityBlocking` blocks every High or Medium in the change at confidence 8 or above, as the CLAUDE.md hard rule requires, so the brief's "never blocks on a re-rating" holds for quality only; the security review's repeats are cut by its narrowed scope instead. A finding already blocking stays blocking.
7. Record start. `flush()` runs an agent only when a pending line is not one the closing start may run (`CLOSABLE`), that is a check or review record, and only where a gate reads it next: before the package and CI-fix pushes, and before the merger after a resume's check. Every other line and the metric line wait for the close. The close's pre-flush and fallback record starts are removed: a line the close did not run is reported as not recorded.
8. Body equality. `contributor.md` passes the file's text unchanged as the body, reads the created pull request, and restores the file's text with the update tool when they differ. `gate_pr_body` refuses a line naming a session. `.claude/settings.json` is already `pr: ""` and `sessionUrl: false`; a footer still added comes from the environment's own pull request attribution, which the Notes ask the user to turn off.
9. Resume trust, dropped. The brief's resume past the push that trusts the run state's records settled at the pushed head is not delivered: the security review found that branch code run by an earlier check could write those records and the branch's own `tools/gates.sh passed`, so the copied records would pass the merge gates' records gate and the security review would be skipped. A resume past the push keeps main's behavior: the check and every review run again at the head, the security review over the whole diff, and only the verdicts this start received build the merge gates' RECORDS or narrow a fix round's review.
10. Non-code stop. The merger reports `body_only` when CI is red only on the scan check and its log names the pull request's title or body. The workflow then starts the contributor in `body` mode (fix the body file, gate it, set it on the pull request; no commit, no push), once per run, and asks the merger again without a fix round. A superseded red is item 5.

## Risks

- Item 9 is dropped, so a resume past the push costs a check and the reviews again; a trusted skip would need records this script verifies itself, left for a follow-up.
- Item 2 leaves the release build to CI on the pull request: a failure there is a red CI and a fix round, not a local failure.
