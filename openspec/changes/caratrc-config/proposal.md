# Proposal

## Why

The JSON configuration is heavy to write by hand: a binding is three levels of nested objects, a stray comma breaks the whole file, and JSON has no comments. The user asked for something simpler, a `.caratrc` of one setting per line in `scope.name value` form, and agreed the grammar. This change replaces the JSON configuration with it and, because the format change touches the files Carat reads, also brings the user and project files that roadmap item 9 (`options-and-config`) planned, with their load order and line-numbered problem reports.

## What Changes

- **BREAKING** `config/default.json` is removed; `config/default.caratrc` holds the same defaults as lines. `~/.config/carat/config.json` and `.carat.json` are never read; `~/.config/carat/caratrc` and the project's `.caratrc` in the working directory are read after the defaults, in that order, later lines winning.
- The grammar: every line is `scope.name value`; the first word is a dotted key and the rest of the line its value, a word, a number, `true` or `false`, or a space-separated list; a word containing spaces is double-quoted (with `\"` and `\\` as escapes inside quotes); `#` at the start of a word starts a comment; blank lines are ignored.
- Scopes: `option.<name>` for the Vim-named options and Carat's `icons`, `theme`, and `timeoutlen` (the top-level JSON keys `theme` and `timeoutlen` become options); `keymap.leader <keys>` for the leader; `keymap.<mode> <keys> <action>` to bind, with `none` to unbind; `plugin.<name>.enabled` and `plugin.<name>.<option>` for plugins; `language.<name>.lsp` and `language.<name>.formatter` for the language commands the language services change will run.
- Every line is validated when the files load: malformed lines, unknown scopes, options, modes, keys, actions, plugins, and plugin options, and values of the wrong kind. Each problem is reported as `file:line: message`, replacing the file name and JSON path, the line is skipped, and the rest of the file still loads; after startup the message row shows the first problem in file order with the count of the others.
- A project `.caratrc` cannot set `language.*` commands, which name programs to run, nor bind a key to a key sequence to replay, which can run any ex command (`:w` to any path included); such a line is reported and ignored, so opening a directory does not choose what Carat executes or writes. It may still bind keys to action names and `none`.
- **BREAKING** (plugin API 2.0) a plugin manifest's default bindings and option defaults, and the bindings of a scratch buffer, are lists of `.caratrc` lines (`keymap.normal <leader>e plugin.explorer.toggle`, `plugin.explorer.width 30`) instead of JSON-shaped hashes, so there is one format; the manifest defaults are applied before the configuration lines by the same code. Option values still reach a plugin as text.
- `config/plugins.json` becomes `config/plugins.caratrc`, one `plugin.<name> <path> <class>` line per compiled plugin, a separate file so the runtime configuration holds no registry lines and the generator reads one small file.
- `carat/domain/default_config.rb` embeds the `.caratrc` text, generated by `bin/carat-gen-config.rb`, and `test/config_sync.rb` checks it and the registry.
- `FilePort` gains `home`, the user's home directory, which only the disk driver reads from the environment.
- `Carat::Json` stays for JSON-RPC; only its configuration uses are removed.
- Docs: architecture sections 1, 6, 7, 8.3, 9, 10, 11, 12, and 13, `CLAUDE.md`, `docs/plugins.md`, `docs/actions.md`, the README (a Configuration section), and the OpenSpec project context.

Roadmap: this change is outside the numbered order, taken now at the user's request; it delivers the user and project configuration files of item 9, which keeps `:set` beyond `filetype` and `syntax` and the buffer- and window-local options.

Out of scope: `:set` for more options, local options, `XDG_CONFIG_HOME`, reloading the configuration while running, user themes, running the language commands (they are validated and kept only), and a migration tool from JSON (the defaults were converted once; a user file is new).

Assumptions recorded here: the leader is set with `keymap.leader` because it is a keymap setting rather than a Vim option (Vim's `mapleader` is a variable); the options Carat validates but does not use yet (`ignorecase`, `smartcase`, `hlsearch`, `incsearch`, `wrap`, `clipboard`) are accepted with their types, as the JSON accepted them; an unknown `icons` set or theme, which the JSON silently ignored, is now reported, because every value is validated; a list option with no words is the empty list; the user file is shown in reports as `~/.config/carat/caratrc` and the project file as `.caratrc`.

## Capabilities

### New Capabilities
- `config-files`: the `.caratrc` format, the three files and their load order, validation of every line with `file:line` reports, and what a project file may not set.

### Modified Capabilities
- `keymap-config`: bindings come from `keymap.<mode>` lines with `none` to unbind and `keymap.leader`; malformed and unknown bindings are reported by file and line.
- `plugin-host`: manifests declare bindings and option defaults as lines under API 2.0; plugins are enabled and configured with `plugin.<name>.*` lines, with unknown plugins and options reported; the registry comes from `config/plugins.caratrc`.
- `color-themes`: the theme is the `option.theme` line, and an unknown theme is reported.
- `icons`: the icon set is the `option.icons` line, and an unknown set is reported.
- `file-explorer`: the explorer is enabled and configured with `plugin.explorer.*` lines.

## Impact

- Domain: new `RcLine`, `RcParse`, `RcParser`, `RcValue`, and `Config`; `Options.from_config`, `Keymap` (lines instead of hashes), `ManifestCheck`, and `RegistrySource` read them; the generated `default_config.rb` changes shape.
- Ports and drivers: `ConfigPort#load` returns a `Domain::Config` and loses `source`; `FilePort#home` in `DiskFiles` and `MemoryFiles`; `RcConfigGateway` replaces `JsonConfigGateway`; `FixedConfig` serves the defaults plus lines a test gives.
- Use cases and adapters: `PluginRegistry` resolves enabled flags and options from lines; `WindowRequests` builds scratch keymaps from lines; `EditorAssembly` collects the problems in file order.
- Plugin API 2.0: `Manifest#bindings`, `Manifest#options`, and `Host#open_scratch` bindings are line lists; the explorer, ruby, and hello plugins and every test plugin are updated.
- Files: `config/default.json` and `config/plugins.json` removed; `config/default.caratrc` and `config/plugins.caratrc` added.
- Tests: new `test/domain_rc_parser.rb` and `test/adapters_config_gateway.rb`; config-touching tests move to lines.
