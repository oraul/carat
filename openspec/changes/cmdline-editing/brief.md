# Brief

cmdline-editing: the user's decision of 2026-11-21 (the design council, decision 2 approved: the basics ahead of the remaining Facet waves; the 'Final 2026-11-21' user-request note on listchars-folds), next in the feature lane after showtabline (#279), as Sprint 25 feature 2 of 3, ahead of `folded-row` (a Facet wave 2 item the planner placed at c281c9b); the planner moves folded-row behind the basics and places `set-options` (Pool 16, with `hidden` on by default, `:colorscheme`, and numeric options such as `showtabline`/`stal`) and a `buffer-picker` with recent files (`<leader>fb` and `<leader>fr`, `<leader>fR` resuming the last search, per the approved keys decision) as the next feature items, then float-painter, ui-groups, and the float/finder/palette speed gate before window-surfaces. Touch no file of the backlog lane (docs/queue-backlog.md, docs/metrics-backlog.tsv). No model name or alias anywhere in names or prose.

Why: the design council's carat user found the command line blocks daily use: it only appends and backspaces at the end (docs/compatibility.md 'Command-line mode', config/default.caratrc keymap.cmdline lines near :800), with no cursor movement, no word or line deletion, and no Tab completion, so every typo in `:e app/models/order.rb` means retyping and every path is typed in full.

The change, as Neovim 0.10 does it: (1) a cursor inside the command line and the search prompts: `<Left>`, `<Right>`, `<Home>` and `<C-b>`, `<End>` and `<C-e>`, `<S-Left>`/`<C-Left>` and `<S-Right>`/`<C-Right>` by word; typed text inserts at the cursor; `<BS>` deletes before it (and still leaves when the line is empty), `<Del>` under it; `<C-w>` deletes the word before the cursor, `<C-u>` everything before it; the cursor is drawn as the bar at its cell, wide characters and the prompt's display width respected; history recall (`<Up>`, `<Down>`) puts the cursor at the end; (2) `<Tab>` completion at the `:` prompt only: an ex command name at the start of the line (from the registered ExHandlers, in docs/compatibility.md's precedence), and a file or directory path for the commands that take one (`:e`, `:w`, `:sp`, `:vs`, `:tabe`, `:r`, `:cd` where implemented), relative to the working directory, through the file port (never a shell), directories ending in `/`; the matches show in the existing popup menu above the command line (Pmenu, PmenuSel, PmenuMatch, as Neovim's `wildoptions=pum`), `<Tab>` and `<S-Tab>` cycle and insert the current match, `<C-n>` and `<C-p>` keep the palette's meaning at the `>` prompt, Esc closes the menu first and then the line; a path outside the working directory is completed only when typed as such (`../`, `/`, `~`); at most a bounded number of entries is read per directory (named in the doc); (3) keymap lines in config/default.caratrc under `keymap.cmdline` with `make gen-config` current, rows in docs/actions.md and docs/compatibility.md (differences listed: no `wildmode`/`wildoptions` options, no `<C-r>` register insert yet, no completion of option names or arguments other than paths), and README's command-line section; (4) the look follows docs/design.md (the popup's frame, the selection, empty state); (5) a table-driven test per key and completion case: movement over multi-byte and wide text, insertion mid-line, each deletion, history then edit, command-name completion, path completion with a directory, a file, no match, many matches, cycling back, a path with spaces, and the bounded directory read. Accepted when make stages pass, `lh` holds 25.0, the popup at the command line allocates within the cursor scenario's budget, and every ADDED scenario names its test. The planner may split it (editing, then completion) by its 3-part rule. Backlog: none.

Plan notes (the split): this delivery covers only the cursor editing at the `:` and search prompts (part 1 above, with the keymap lines, the docs rows, README, and the tests of movement, insertion, deletion, and history then edit); Tab completion, the popup menu, and the bounded directory read are queued as `cmdline-completion`.
