# Brief

architecture-review — sprint 5's fifth and last merge, the queue head, the user's request in their words: "review the architecture and the holes in it... it should be expansible, easy to read and do maintenance, sometimes something became redundant there". Produce a recorded report (committed under the archived change) that checks docs/architecture.md and docs/codebase-map.md against the code at main for: holes (a feature with no extension point, a rule the code breaks, a missing port or seam), redundancy (two mechanisms for one job, dead code, docs repeating or contradicting each other), and reading or maintenance costs (expansibility, readability, maintainability). Each finding carries its location, why it matters, and a fix outline, and is appended to the end of docs/backlog.md with >> so the planner queues it. Correct docs/architecture.md (and the code map) only where they disagree with the code; no code fix lands in this change. The queue entry names the sprint-4 sweep's entries in docs/backlog.md as inputs; during a delivery the backlog is never read, so do not read it: review from the code and the docs, and the planner's sprint mode removes duplicates. It may be large; split at its start if it is more than one reviewable pull request. No reordering of the queue. The pull request is opened by the branch-push Action from pr.md; never call a pull request create tool. During the delivery never read or grep docs/backlog.md, not even through a repository-wide search (always pass --exclude=backlog.md or search only named paths), a grep --include, or a tail to copy the entry format (append only with >>). Keep to exactly this; name anything extra and ask.
