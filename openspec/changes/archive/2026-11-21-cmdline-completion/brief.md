Why: the design council's carat user types every path in full: `:` has 0 completions (config/default.caratrc keymap.cmdline has no `<Tab>`), so `:e app/models/order.rb` is typed letter by letter.
The change, as Neovim 0.10 does it with `wildoptions=pum`: `<Tab>` at the `:` prompt only completes an ex command name at the start of the line (from the registered ExHandlers, in docs/compatibility.md's precedence) and a file or directory path for `:e`, `:w`, `:sp`, `:vs`, `:tabe`, `:r`, `:cd` where implemented, relative to the working directory, read through the file port (never a shell), directories ending in `/`; a path outside the working directory is completed only when typed as such (`../`, `/`, `~`); at most a bounded number of entries is read per directory (carat/ports/file_port.rb `list` reads every entry today; the bound is named in the doc); the matches show in the popup menu above the command line (Pmenu, PmenuSel, PmenuMatch, the look of docs/design.md: frame, selection, empty state); `<Tab>` and `<S-Tab>` cycle and insert the current match at the cursor #281 added; `<C-n>` and `<C-p>` keep the palette's meaning at the `>` prompt; Esc closes the menu first and then the line; keymap lines under `keymap.cmdline` in config/default.caratrc with `make gen-config` current, rows in docs/actions.md and docs/compatibility.md (differences: no `wildmode`/`wildoptions` options, no completion of option names or arguments other than paths), README's command-line section. A table-driven test covers command-name completion, a directory, a file, no match, many matches, cycling back, a path with a space, and the bounded directory read. Accepted when make stages pass, `lh` holds 25.0, the popup at the command line allocates within the cursor scenario's budget, and every ADDED scenario names its test. Backlog: none.
