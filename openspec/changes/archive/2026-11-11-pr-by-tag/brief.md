# Brief

pr-by-tag — The user's decision: pull requests are created by GitHub Actions on GitHub's own runners, started by a pushed tag, and the delivery then merges them as today. Read decision 18 of tmp/briefs/pipeline-skeptic.md first and deliver exactly it. Why: probes 106 and 107 proved with curl and gh traces that the bytes leave this session clean and Anthropic's cloud network layer appends a 'Generated by Claude Code' footer (session link on a create, a general link on an edit) to every pull request create and edit made over GitHub's API from a cloud session; settings.json attribution does not reach it; git pushes arrive clean. Deliver: (1) after the branch push, the contributor pushes an annotated tag pr/<branch> on its head whose message is the title line, a blank line, and the gated body file; (2) .github/workflows/open-pr.yml on push of tags pr/** reads title and body from the tag, runs main's tools/gates.sh pr-body and tools/scan_text.sh on them (main's copy), refuses a branch that does not exist or is not of an allowed type, creates the pull request with gh pr create, reads it back and fails unless title and body match byte for byte, and deletes the tag; the job that creates the pull request declares `environment: AI` and authenticates gh with the secret PR_TOKEN of that GitHub Actions environment (the user created the environment AI and its secret PR_TOKEN; it is not a repository secret, and an environment secret reaches only a job that names the environment; never GITHUB_TOKEN, whose events start no CI); (3) the delivery waits for its branch's pull request to appear, records the number, and continues to CI and the merger's squash-merge; (4) the contributor never calls a pull request create tool or API, and the agent files, workflow, CLAUDE.md, README, and map say so; (5) bring over only the check-clone fix of commit 9a828bb from branch chore/publish-pr (the detached check passes CARAT_BIN=build/dev/carat), which this change needs to pass its own check; tools/publish_pr.sh is not brought over; (6) the guard lets the contributor push only pr/ tags. Accepted with tools-test cases (tag message parsed into title and body, a gate-failing body refused, a bad branch refused) and this change's own pull request opened by the tag workflow (read from the tagged commit), its edit history holding no footer revision. If the PR is not created when the tag is pushed (a missing secret, or a protection rule of the AI environment such as required reviewers or allowed refs), read the Action's log, report it with the reason, and wait; do not fall back to the pull request tool. For the planner: pr-by-tag replaces publish-pr (PR 105 closed unmerged at the user's word, its run superseded) and runs before sprint-planning and ci-time.
