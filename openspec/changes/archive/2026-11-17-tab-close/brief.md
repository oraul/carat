The user's report: "I enter on home using `carat .`, open `space e` for the explorer and choose a file opening a new tab, so now I have a no name tab and the tab with my file; the first tab doesn't close when I go there to quit it. It also happens when I open a file from the explorer in the same tab and then open the next one in a tab: the first (initial) tab doesn't close, and after that it becomes buggy."
Reproduced at c848525 in a real pty (110x30, a directory with alpha.txt and beta.txt): (A) `carat .`, `<Space>e`, `jj` onto alpha.txt, `t`: the row shows `[No Name]` and `alpha.txt`, tab pages 1 and 2; `gT` swaps tab page 2's window to `[No Name]` (gt follows buffers); `:q` closes tab page 2 and the `[No Name]` tab stays in the row; a second `:q` closes the explorer, `[No Name]` and the hidden alpha.txt remain. (B) `l` on alpha.txt (reuses the startup buffer, correct), then `t` on beta.txt, `gT`, `:q`: tab page 2 closes, alpha.txt and beta.txt both stay in the row. (C) after (A)'s `t` and `gT`, `:bd` on `[No Name]` closes every window showing it, tab page 2's and tab page 1's file window, leaving tab page 1 with only the explorer filling the screen; `<Space>e` there gives "E444: Cannot close last window".
The user's decisions: asked what should close a buffer tab, the user answered ":q closes it too: when other buffer tabs exist, :q on a file closes that file's tab and the window shows the next file; on the last file it quits the editor as now; :bd and <leader>bd also close the tab and keep the window and the explorer as they are."
This part, three fixes, all under `option.gt buffers` (`Options#gt_follows_buffers?`, the default, the top row showing buffer tabs); under `option.gt tabpages` today's Vim behavior stays, except that no fix may leave a tab page with only side windows in either mode:
(1) :q closes the buffer tab: where `:q` (`carat/use_cases/files/quit.rb`, the last-window rule, a file window beside only side windows counting as the last) would end the editor and another listed file buffer exists, it closes the current buffer's tab instead: the buffer leaves the list as `:bd` would, E37 for a modified one under `:q` as now, `:q!` discarding its changes, `:wq` and `:x` after their write; the window shows the next listed file buffer, or the one before; side windows stay. On the last listed file buffer every way quits as now (the hidden-buffer E37/E162 check unchanged). `:qa`, `<leader>qq`, and `<C-w>q` closing a split window keep their rules.
(2) The startup buffer leaves: the unnamed, empty, unmodified startup buffer (`carat/domain/buffer_list.rb:324` names it) leaves the list, the row, and `:ls` once a file buffer opens in another window or tab page, the window that showed it showing the opened file; opening in its own window keeps today's reuse.
(3) :bd keeps the layout: `:bd`, `:bd N`, and `<leader>bd` (`carat/use_cases/buffers/delete_buffer.rb`) show the replacement buffer in every window that showed the deleted one instead of closing those windows (the next listed file buffer, or the one before, or a new empty buffer when none is left), side windows untouched; and the explorer toggle never ends on E444 when the explorer is the last window.
