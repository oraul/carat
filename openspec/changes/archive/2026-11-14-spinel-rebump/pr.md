build(toolchain): bump spinel to 6b43fe94

## Summary

Moves the Spinel pin from f34005bf to the upstream head 6b43fe94, with the vendored runtime header regenerated by `make spinel-header` and every check passing on the new toolchain. The pin was 878 commits behind, and since Spinel 84aa303b1 `String#byteindex` raises `IndexError` for an offset on a continuation byte, which made two tests fail and could raise in the editor on text that is not UTF-8 or inside a multibyte collection of a pattern. A new `Domain::Utf8.boundary` moves each search offset past continuation bytes first, so every ASCII needle finds what it found before.

---

## Changes

- Bump `SPINEL_REF` in the Makefile to 6b43fe94 and regenerate `tools/spinel/spinel_rt_responds_generated.h` at the new pin with the unchanged generator port.
- Add `Domain::Utf8.boundary`, which skips the continuation bytes at a byte offset, allocating nothing.
- Fix the byteindex searches of `TextLines`, `VimPattern`, `ExRange`, `MarkdownText`, `RpcFramer`, and the plugin host's `read_file` to start at a character boundary, with the two lines inlined in `PluginApi::Paths.segments`, since `plugin_api.rb` requires nothing.
- Add test rows for the helper, a pattern collection with a multibyte character, a framer header line that starts with a continuation byte, and a plugin file read of a line that starts with one.
- Document the boundary rule in `docs/spinel-notes.md` and the helper in the code map.
- Record the planner's queue, the metrics row of the last merged change, and the five quality advisories in the backlog.
