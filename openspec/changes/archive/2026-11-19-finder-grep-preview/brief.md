# Brief

finder-grep-preview: a feature the user asked for (T2 user request, estimated medium, 2026-11-19: "The finder grep it doesn't show the preview file like the finder file"), queued in the feature lane after finder-grep-c and finder-match-strict, before vim-folds-c. The plugin requires only carat/plugin_api.rb and its own files; no new host request.

Problem: the content search picker (<leader>fg, plugin.finder.grep) never shows the preview float the file finder shows on a terminal of PREVIEW_COLUMNS or more (carat/plugins/finder/plugin.rb:320: preview = !@grep && cols >= PREVIEW_COLUMNS).

Change: on a wide terminal the grep picker shows the same preview float beside its list, same layout and sizing as the file finder. It shows the highlighted row's file around its matched line: the window of lines is chosen so the matched line sits in the middle of the preview (clamped at the file's start and end), and the matched line is marked (the same highlight the file finder uses for its selection, or the theme's search match colour; reuse an existing style, no new colour). The preview follows the highlighted row as it moves and as the query changes, and is built from the text the picker already read at open (no file read per key or per move). Preview text is untrusted and goes through the same safe-text path as the rows (control bytes, invalid UTF-8, bidi and format code points). On a narrow terminal there is no preview, as today. An empty result closes the preview.

Tests (table-driven, snapshots, through make): preview shown at the wide threshold and absent below it; the matched line centred, and clamped near the top and bottom of a file; the preview following a move and a query change; an empty result with no preview; a file with control bytes previewed safely; the file finder's preview unchanged. docs/plugins.md's finder section and the code map updated. Allocations per key on the existing scenarios held. Accepted when those tests pass, make check passes, and the grep bench's time per key (from finder-grep-b) does not regress. Backlog: none.
