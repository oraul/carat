# Proposal

## Why

A Vim user holds Ctrl through a window command: `<C-w><C-w>`, `<C-w><C-h>`, `<C-w><C-j>`, and so on. Carat binds only the plain second key (`config/default.caratrc:113` to `:125`), so with Ctrl held the `<C-w>` prefix is followed by a key it does not know and the command is dropped, in a file window and in the explorer tree alike. The user asked for the held-Ctrl forms; it is the user-requested feature the every-three rule of `docs/goals.md` asks for now.

This rounds out roadmap item 7 (windows and tab pages), whose windows half is delivered; it adds no new window behavior.

## What Changes

- Bind `<C-w><C-s>`, `<C-w><C-v>`, `<C-w><C-h>`, `<C-w><C-j>`, `<C-w><C-k>`, `<C-w><C-l>`, `<C-w><C-w>`, `<C-w><C-p>`, `<C-w><C-o>`, and `<C-w><C-q>` in normal mode to the action of their plain form, in `config/default.caratrc`, with the generated mirror `carat/domain/default_config.rb` regenerated by `make gen-config`. A count before `<C-w>` works as with the plain form, because the action is the same.
- Leave `<C-w><C-c>` unbound: Vim's help (`CTRL-W_CTRL-C`) says the `<C-c>` cancels the command instead of closing the window, and carat already drops a `<C-w>` followed by an unbound key. A test pins that it changes nothing.
- Add rows to `docs/compatibility.md` for the held-Ctrl forms and replace the Differences clause that says the `<C-w><C-x>` aliases arrive later.
- Add table rows to `test/editor_windows.rb` (file windows), `test/editor_explorer.rb` (into and out of the tree, both ways), `test/domain_keymap.rb` (the lookup of each new chord), and `test/domain_keys.rb` (two Ctrl keys in one keys word).
- Planner bookkeeping beside the code: the every-three clarification in `docs/goals.md` and `.claude/agents/planner.md`, and the new `docs/queue.md` with this change removed.

Out of scope: `<C-w>` followed by a count (`<C-w>3<C-j>`), `<C-w><BS>` and the arrow-key forms, the held-Ctrl forms of window commands carat does not implement yet (`<C-w><C-t>`, `<C-w><C-x>`, `<C-w><C-r>`, and the rest), and any key in a mode other than normal.

### New Capabilities

### Modified Capabilities
- `windows`: a requirement that the held-Ctrl forms of the window commands act as their plain forms, from a file window and from the explorer tree, and that `<C-w><C-c>` changes nothing.

## Impact

- `config/default.caratrc` and the generated `carat/domain/default_config.rb`: ten new `keymap.normal` lines. No Ruby code changes, no new action, so `docs/actions.md` is unchanged.
- Tests: `test/editor_windows.rb`, `test/editor_explorer.rb`, `test/domain_keymap.rb`, `test/domain_keys.rb`, with their snapshots.
- Docs: `docs/compatibility.md`, `docs/goals.md`, `docs/queue.md`, `.claude/agents/planner.md`.
- Allocations per key: unchanged; the keymap trie gains ten leaves under the existing `<C-w>` node, and the lookup of other keys does not pass through it.

Assumptions: the held-Ctrl forms follow the plain forms' counts in carat (so `<C-w><C-p>` and `<C-w><C-o>` take none, as `<C-w>p` and `<C-w>o` do); `<C-w><C-W>` is the same code as `<C-w><C-w>`, so `<C-w>W` has no held-Ctrl form, as in Vim.
