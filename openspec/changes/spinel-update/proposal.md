# Proposal

## Why

`SPINEL_REF` pins Spinel at 93d7883bd8d85ebbce768445c41c03d9a4bc9e92, and upstream's default branch has moved 193 commits since: its head is c0502112d8cf8c6f57bc7e1ef5a2af1732407036 (2026-11-16), which `git ls-remote origin HEAD` on the remote `make toolchain` clones reported when this change started. The user asked for the bump now (queue pool item 63, `spinel-bump`, renamed `spinel-update` because a change of that name merged as #95), in its own pull request as the Makefile and `CLAUDE.md` require, with the vendored header regenerated by `make spinel-header`, the toolchain rebuilt by `make toolchain`, and every stage of `make check` passing.

## What Changes

- `SPINEL_REF` moves from 93d7883bd8d85ebbce768445c41c03d9a4bc9e92 to c0502112d8cf8c6f57bc7e1ef5a2af1732407036, 193 commits apart (`git rev-list --count`; the old pin is an ancestor of the new).
- `tools/spinel/spinel_rt_responds_generated.h` is regenerated at the new pin with `make spinel-header`, run with the 93d7883b toolchain before `make toolchain`.
- Whatever carat needs to stay green at the new pin, fixed in carat's code rather than worked around, each fix named in the tasks and the pull request, and any new pitfall recorded in `docs/spinel-notes.md`.

No editor behavior changes: the editor answers as it does on main at 93d7883b.
