# Tasks

## 1. Agent guard

- [x] 1.1 `tools/agent_guard.sh`: a lexer that splits a Bash command into words, operators, and redirections as the shell does and refuses expansions, substitutions, ANSI-C quoting, subshells, here-documents, globs, braces, and a leading `~`; `field` decodes a `\u` escape of a printable ASCII character. Tested by the `tools/tools_test.sh` bypass cases of every profile ("guard: PROFILE refuses ANSI-C quoting", "... a variable", "... a subshell", "... a command substitution", "... env", "... xargs", "... sh -c", "... a parent step", "... a quoted name", "... reads a JSON escape as its character", and the rest of the loop).
- [x] 1.2 `tools/agent_guard.sh`: the forms of the `read`, `merger`, and `contributor` profiles, each simple command judged against its profile's forms, and the shared word rules (parent step, run state's directory). Tested by the per-profile allowed and refused cases ("guard: PROFILE allows a git read", "guard: read refuses a make target it does not list", "guard: merger refuses the deletion of main", "guard: contributor refuses a command in a make variable", and the others) and the dry run of each agent's commands ("guard: scout runs its steps" to "guard: contributor reads lines and the tree").
- [x] 1.3 `tools/agent_guard.sh`: one write-target judge for redirections, writing commands, and file tools (project, `.git/`, `build/` itself, run state's directory, DIR, the body file never a link). Tested by the write-target and body-file cases, in a real tree among them ("guard: contributor refuses a redirection through a linked directory", "guard: contributor refuses a write to a linked body file", "guard: contributor refuses a removal of the run state's parent").
- [x] 1.4 `tools/agent_guard.sh`: the header lists every profile's forms, worded as the code behaves (a link target refused only when its parent step follows a missing directory).
- [x] 1.5 `tools/agent_guard.sh`: the quality review's fixes. A line break reaches `lex` marked, so a comment ends at it with no continuation; only a bare digit run is a descriptor; `sort` takes a listed set of short options; the git read verbs refuse a prefix of a long option that writes or runs a command and `git grep` a short cluster holding `O`; `git -C` takes only the project or a worktree `tmp/.NAME`. Tested by the cases "guard: PROFILE refuses a line continuation inside a comment", "guard: PROFILE reads a comment to its line break only", "guard: PROFILE refuses a repository of its own by -C", "guard: PROFILE allows -C of the project and of a worktree", "guard: read refuses sort -o in a cluster", "guard: read refuses a long sort option by its prefix", "guard: read refuses a sort compress program", "guard: read refuses git grep -O in a cluster", "guard: read refuses git grep's pager by a prefix", "guard: read refuses textconv by a prefix", "guard: read refuses a quoted digit before a redirection", and "guard: read refuses an escaped digit before a redirection".
- [x] 1.6 `tools/agent_guard.sh`: the security review's fix. `sh tools/metrics.sh measure` writes only `build/metrics/current.tsv` of the project or of a worktree `tmp/.NAME`, no link on its way, followed by scenario names; `compare` takes BASE and CURRENT. Tested by the cases "guard: read refuses a measurement into .git", "guard: read refuses a measurement outside the project", "guard: read refuses a measurement into another project file", "guard: read refuses a measurement into the toolchain", "guard: read refuses a measurement with other than scenario names", "guard: read measures into the project or a worktree and compares", and the real-tree cases "guard: read refuses a measurement through a link in a worktree" and "guard: read refuses a measurement through a link in the project".
