# Design

## Context

From Spinel 2440954d1 on, a call plan question during code generation (`elab_point_of`) rebuilds the load record whenever the node table changed since its last build, and each `[]` on an `untyped` receiver asks it twice (the `[]`, then a `new`). `SP_TIMING` counts the rebuilds as `phase=an_elab_points ... builds=N`. untyped-elephant (#124) and untyped-gateway (#128) left the runner at 779 rebuilds at 6b43fe94.

The measurement toolchain is Spinel's newest commit, b582d53e, built under `tmp/.spinel-new` and `tmp/.toolchain-new` with the local trace in `elab_fresh` (`SP_ELAB_TRACE`) that names the method generated, the call that asked, and the source position last emitted. Its vendored header was generated by the port with the nine Symbol false positives Spinel's own generator now lists; the pinned toolchain stays at 6af548c9. The runner is compiled as `make test-build` compiles it, with its own `SPINEL_CACHE_DIR`.

At main (d8bbb58) with b582d53e: 731 builds, `an_elab_points` 63.9 s within `cg_methods` 103.6 s, analysis 134.7 s, 4 min 32 s in all on four cores. By generated method: `JsonRpcLanguageGateway` 188 (`receive` 52, `signed` 26, `initialized` 18, `diagnostic_of` 16, `notified` 14, `add_target` 14, `candidate_of` 12, and smaller); `DomainGrammarTest#run` 60; `EditorCmdlineTest#main` 36; FileUtils 26; `EditorVisualTest#main` and `EditorRegistersTest#main` 24 each; `SymbolOutline` 18; `LintTest` 46 over six helpers; and about forty other test helpers and `main`s at 2 to 16 each.

## Goals / Non-Goals

**Goals:**

- Remove carat's own untyped `[]` calls that the trace names, production and tests, with behavior and every snapshot unchanged and every stage green at 6af548c9, so the bump in part b compiles near today's time.

**Non-Goals:**

- Moving `SPINEL_REF`, the vendored header, the header generator (part b).
- The bundled FileUtils and the rebuilds Spinel makes without a carat `[]` (its own synthesized code).

## Decisions

- The gateway and `SymbolOutline` read through `Carat::Json.field` and `Carat::Json.element`, the readers untyped-gateway added: each read was already guarded by `is_a?(Hash)` or `is_a?(Array)` on its receiver, or by a guard that implies it (a `label` that is a `String` only when `chosen` is a `Hash`), so the reader answers exactly what `[]` answered, and the `x.is_a?(Hash) ? x["k"] : nil` forms become `Json.field(x, "k")`. Alternative: typed records per message, rejected as before, a rewrite for the same effect.
- A test helper or loop that indexes an untyped array reads it through `Carat::Json.element`, whose `is_a?(Array)` check narrows the untyped argument before the `[]` on a receiver typed `Array`, so its body costs nothing per call; `DomainGrammarTest` wraps it as `at`, and `LintTest`'s character scans read a `String` copy of the line (`text = line.to_s`). A bare local reader `(Array[untyped], Integer) -> untyped` given an untyped argument was not used, since nothing narrows that argument. Alternative: a public element reader in `Carat::Testing`, rejected for now: the tests call their helpers as module functions, not on the `Testing` instance, and one line per file is clearer than a new library method.
- The trace prints the last source position emitted, not the asking node's, since a call node carries no line: a rebuild is attributed to the statement being generated, enough to find the `[]`.

## Risks / Trade-offs

- [A read whose receiver is not guarded changes from `[]` on another kind (a `String`'s substring) to nil] → every rewritten read was checked against its guard; none reads an unguarded receiver.
- [The figures depend on the Spinel commit] → The rebuild count is deterministic for a commit and the source; the seconds are machine dependent and given only beside it.
